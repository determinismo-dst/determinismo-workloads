== Changes to earlier entries ==
 D12 (round 1, equal values with different hashes): CHANGED in part. CHAMP's `get` (champ.hpp:536-561) walks the
   query's hash 5 bits a level and, at the first data slot it meets, asks only Equal{}(stored, query): it never
   compares hashes. So two `=` values whose hashes agree in their low bits find each other as long as the stored one
   sits above the level where the bits differ. 0.0 (hash 0) and -0.0 (hash 0x80000000) differ only in bit 31, i.e. at
   level 6, so in small sets and maps they DO find each other:
       (contains? #{0.0} -0.0)          ; round 1: jank false   replica: jank true (= Clojure)   -> round-1 example RETRACTED
       (count (hash-set 0.0 -0.0))      ; jank 1 (= Clojure; the set holds -0.0, IM1)
   and fail only when the stored one is pushed below level 6, e.g. by a key whose hash shares the low 30 bits
   (2.0's hash is 0x40000000):
       (contains? #{0.0 2.0} -0.0)      ; Clojure true    jank false
       (count (conj #{0.0 2.0} -0.0))   ; Clojure 2       jank 3
   1 and 1N (hashes 1392991556 and 2654435770) differ in the low 5 bits: round 1's examples (count (hash-set 1 1N)) = 2,
   (get (hash-map 1N :a) 1) = nil, (count (hash-set [] (lazy-seq nil))) = 2 are confirmed. The shape dependence is new:
   whether 0.0/-0.0 are one key depends on the other keys present.
   The replica adds three consequences of the same cause (not new causes):
   - promotion: an array map finds 1N as 1 (runtime::equal), but at 8 entries any assoc promotes to a hash map, where
     1 and 1N are different keys:
       (count (assoc (into {} (map vector (range 1 9) (repeat 0))) 1N :x))   ; Clojure 8   jank 9
   - hash-map `=` follows lookups: (= (hash-map 1 0) (hash-map 1N 0)) is false in jank (Clojure true), and
     (= (hash-map 0.0 0) (hash-map -0.0 0)) is true but the two hashes differ (search M1d, both classes);
   - map `=` is not symmetric across array and hash maps:
       (= {1 :a} (hash-map 1N :a))   ; jank false     (= (hash-map 1N :a) {1 :a})   ; jank true   (Clojure true, true)
 R13 (round 2, literal duplicates accepted): CHANGED in its second example. The reader builds a set literal with a
   transient insert per element (parse.cpp:722-749, `set.insert(item.ptr)` → add_mut); its duplicate check is a
   std::unordered_map keyed by full hash, which misses 0.0/-0.0, but the CHAMP insert then finds 0.0 at level 0 and
   replaces it: (count #{0.0 -0.0}) is 1 (the set holds -0.0), not 2 as round 2 said. The literal is still accepted
   where Clojure's reader rejects it (R13 stands); `{1 :a 1N :b}` is unchanged ({1 :b}, an array map).

== 3. Left out, and why ==
 - rrbtree / relaxed nodes / flex_vector / concat / slice_left: immer::vector never builds them (jank has no flex
   vectors; subvec copies through from_range).
 - champ update/update_if_exists/diff/equals (operator==), for_each_chunk: not called by jank (jank's map and set `=`
   are its own, base_persistent_map.cpp:31 / persistent_hash_set.cpp:55, modeled).
 - Memory as bytes: allocation sizes (packed vs max), buffer capacities, `destroy_n` beyond the logical count. The
   replica keeps each buffer's physical slots as a list; reads past them are UB and return none.
 - The GC itself: GC_free is recorded (freed ids), collection and address reuse are not modeled (IMA1).
 - Iterator caching inside rbtree_iterator (curr_ per leaf base): equivalent for a tree that does not change while
   iterated; jank iterates only persistent vectors (transients are not seqable).
 - Seq objects (persistent_vector_sequence, base_persistent_map_sequence, iterator_sequence) as objects: only their
   element order is modeled; their in-place mutation is round 2's R117.
 - Metadata, identity of boxed objects beyond the value kinds, keys of every kind: keys are round 1's values
   (keywords, longs, 1N, doubles, strings, chars, vectors/lists of those); metadata examples are by reading.
 - CHAMP laws other than get-after-add (lookups of other keys after add, dissoc, count = elements, preservation
   of the well-formedness invariant, the transient add_mut): not proved. Lookups of other keys need an equality that
   is an equivalence agreeing with the hash, which jank's is not (D12, R55); get_add needs neither. The CHAMP
   replica is otherwise checked by the searches (do_check_champ-style structure check after every step) and by a
   self-test against a list model under six hash functions (identity, coarse buckets, splits at depth 6, constant
   hash = all collisions, bit 31, a multiplicative hash), persistent and transient, 200 scripts of 60 operations
   each: all agree.
 - Element laws over the transient push and take paths (nth after conj!/pop!): not proved (their counts are, and
   nth after assoc! is); they are searched (V worlds) with the aliasing check.
 - Vectors past 2^35 + 32 elements: push_back would make a root at shift 35, which visit_regular_descent does not
   handle (IMMER_DESCENT_DEEP is 0, config.hpp:120; position.hpp:1145 IMMER_UNREACHABLE). Not reachable in practice
   (2^35 object_refs = 256 GiB); the laws assume fewer than 2^35 elements.

== 4. Assumptions ==
 Replaced:
 - Round 1 A3 (immer abstracted: vectors are Lists, sets in insertion order, lookup "same hash then equal"):
   replaced by the replica. Vectors: confirmed (theorems). Sets: order is CHAMP's, insertion order contradicted
   (no round-1 result used it). Lookup: refined (the query's 5-bit hash digits choose the path; Equal{}(stored,
   query) at the first data slot met, or over a collision node at depth 13; full hashes are never compared).
   Insert: contradicted (immer keeps the last of two equal elements, round 1 kept the first: IM1).
 - Round 2 "Libraries with no source here: immer": replaced (immer 282629d0 read and replicated).
 New or standing:
 - IMA1. bdwgc scans node and values memory conservatively, so an owner token (a 1-byte GC allocation,
   gc_transience_policy.hpp:52) stays allocated while any node holds it: tokens are never reused. Modeled as fresh
   ids.
 - IMA2. Mutation in place is modeled as replacement with the same identity. This is the C++ semantics when every
   object owned by a live transient's token is reachable once and from no other live value, and no freed object is
   reachable; the `aliasing` check verifies exactly that after every step of every searched timeline (self-test:
   the check fires on a transient that shares a persistent vector's token).
 - IMA3. Release build (NDEBUG): immer's asserts are off; IMMER_TAGGED_NODE=0 (CMakeLists.txt:113): a node read with
   the wrong kind is UB (none in the replica).
 - IMA4. x86-64: size_t 64 bits, `char` signed (keyword/string hashes), std::hash<object_ref> zero-extends the u32.
 - IMA5. jank's `=` and hash are round 1's jankEq/jankHash (Jank/Equality.lean, updated for 7135b7708 in round 2),
   fuel 12, for the value kinds used as keys.
 - IMA6. Values are distinct objects (no identity shortcuts): `persistent_vector::equal` checks `&o == this`, which
   only matters for values that are not equal to themselves (NaN, R55's string seq); not searched.
 - IMA7. Transient users rebind to the transient each bang returns (the documented use); a promoted array-map
   transient's old handle is not used again.

== 8. Library gaps filled (sdk/lean untouched; all in Jank/R3/Immer/) ==
 - Object identity and in-place mutation without a heap: nodes carry an allocation id and an owner token; mutation
   is replacement under the same id; the `aliasing` check (Maps.lean) makes that exact by verifying, after every step,
   that objects owned by a live transient's token are reachable once and from no other live value, and that no
   GC_free'd object is reachable. Fresh ids/tokens are threaded explicitly (Rbts) or through `StateM Al` (Champ).
 - Census with property classes and first examples per class, explore over SplitMix-mixed seeds, timing and flushed
   output per search, selectable searches per run (Kit.lean, driver): exhaust stops at the first violation, so classes
   are counted with a census and set aside by name or by removing their trigger from the alphabet. The census runs in
   time-budgeted segments with checkpoint lines and prints a resume path; the driver takes `ID>path` to continue it
   and `ID@v` for the partition with first decision v (Kit.censusFrom, nextPathUnder); summarize.py merges segments.
 - Keys with a chosen hash: the inverse of jank's hash::integer (HashInv.lean, proved), so collision structure at a
   chosen CHAMP depth, and full 32-bit collisions, are drawn with plain long literals.
 - Proof-friendly replicas: every replica function recurses on a level number (structural), so `decide`/`rfl` run
   concrete programs in the kernel (Findings) and induction proves the laws; `Float` is opaque to the kernel, so
   examples with doubles are evaluated with #eval (.r3-scratch/immer/examples.lean, output in results).
 - Slot contention: every build and search went through bin/job, one census segment (at most 18 minutes) per job.
