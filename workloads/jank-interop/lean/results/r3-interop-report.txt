3. LEFT OUT, AND WHY
  - Class template instantiation in Lean: checked by reading instead. SemaTemplate.cpp:5639-5650 converts an Integral argument back to an expression and re-checks it against the parameter, so (std.array int 3) is the same specialization as C++'s std::array<int, 3>. Negative sizes and narrowing to `bool` fail as in C++. Nothing to search.
  - GetOperator's real lookup (current scope, ADL namespaces, hidden friends): modeled as finding nothing for the user's classes (CXA10).
  - GetTypeAsString and jank's qualified type names: round 2's printer is reused, for messages only.
  - Ranking tie-breakers not modeled: derived-to-base distance, more-specialized templates, constraints. Variadic or defaulted template deduction, member function templates, and the order of overload sets in resolve_scope (no searched program depends on them).
  - Codegen of the new worlds: types are searched, not the emitted C++. "JIT error" claims come from C++ rules.
  - nREPL/eval paths for native exceptions: read, not searched (the nREPL agent's area).
    - evaluate.cpp:safe_eval:733-778 has a catch-all. A native exception of any type becomes *e = ex-info "uncaught exception", and the native value is lost.
    - nrepl/server/core.jank:handle-client:85-104 catches std::exception, object_ref and error_ref only. Another native exception escaping the handler reaches the client future's (catch :default _) (142), which ends that client's loop without a reply.

  - `(:const (:array T n))`: CppInterOp's QualType::getCanonicalType keeps the const on the array node, while Clang-built arrays carry it on the elements. Not searched (CXA12).
