ROUND 3 — nREPL evaluation wired to the reader, analyzer and evaluator replicas
(area Nrepl, exe jank3-nrepl, deviation prefix N; jank 7135b7708, paths under
upstream-main/compiler+runtime/; search outputs in results/r3-nrepl.txt)

What changed from round 2: the nREPL model's program table is gone. An eval now runs jank's real
path. do-eval → safe_eval → eval_string reads ONE form with the reader replica, builds the objects
parse.cpp builds (source_to_meta under the thread's *ns*/*file*), and analyzes the form with a fresh
analyzer replica against this process's namespaces and vars. It evaluates the form with effects
(vars, thread bindings, output on FILE* stdout through the fd table and the capture), then reads
the next form. *1/*2/*3/*e are set on the connection thread's binding boxes. The value is printed
with pr-str and the bencode replies are written.

The spec is a Clojure process: the LispReader replica per form, then Compiler.eval (macroexpand,
then a top-level do split into its forms). After that come the Compiler.analyze replica
(cljAnalyze), an evaluator with effects, and Clojure's core macros and functions.

Each mismatch is labelled by replaying its timeline on a spec "variant" that adopts one known jank
behavior. Residual searches turn the found variants on, so the two processes do not diverge on a
known class.

No sorry, no native_decide, no new axioms. Round 1/2 files untouched.

3. LEFT OUT, AND WHY
======================================================================
- The JIT itself: fn/let/loop/try bodies are given Jank.Analyzer.Eval's meaning. The interpreted
  top level (evaluate.cpp) and compiled bodies are not told apart, so R37's operand order is not
  re-run here.
- try/catch, binding, letfn, loops: Eval.lean does not model try; the grammar avoids these.
- Doubles, ratios, chars, regexes, syntax-quote in code strings: outside the grammar (the reader
  conversion reports them unsupported).
- line/column fields: they only enter :jank/source :start/:end, which no property reads.
- Macro bodies' own output during expansion is dropped (NA5).
- The interrupt op (R128, absent in jank), stack overflow in an eval (R129: the evaluator's fuel is
  a bound, reported as outside the model), and fd exhaustion (R135) are not re-run.
- Complete runs at ≤2 preemptions where the tree outgrew a 20-minute job:
  - T9 (two evals per connection): ≤1 complete; ≤2 stopped at 853,000.
  - T7 (partial reads): ≤1 stopped at 1,500,000; ≤2 stopped at 1,489,000. Every read decides a
    split and a length, so the trees are large.
  - Round 2's controls with round 2's partial reads: ≤2 control 0 stopped at 1,762,000.
  Round 2's controls were therefore completed with whole-message reads. Read chunkings are covered
  by round 2's complete chunking census and by T7's runs.
  An exact partition command (t-range/r2-range: prefixes 0^i j) can finish the rest: T9 has 216
  decisions on its all-zero timeline, and partition 0..1 alone is complete over 94,849 timelines,
  nothing. Estimated ~10M timelines, hours of a shared slot, so not run.
- Observed outside the nREPL area, not searched: jank's terminal REPL looks up *e
  (terminal_repl_client.cpp ~317) but never sets it on an error (its handlers only print).

  overlapped: R126/R132/R136 reproduce).

New:
- NA1. An nREPL eval runs clojure.main/repl over the code string within the session's bindings: a
  :value per form, *3/*2/*1 per form, an exception caught (eval-error, *e) and the loop goes on.
  Only N5 depends on it; every other search uses load-string mode.
- NA2. load-file is Clojure's load of the content (Compiler.load: forms in order, the first
  exception ends it, *ns* bound for the load). The reply's :ns is the session's *ns* afterwards
  (N4).
- NA3. The accept loop conveys *ns* = user to each connection thread (R111's resolution namespace).
- NA4. Granularity in World T: a form's read, its analysis and its evaluation are one step each;
  each fwrite/putc is one step after its evaluation. Global effects of one form are atomic.
- NA5. Macro bodies print nothing (their output during expansion is dropped).
- NA6. Clojure's namespace print: #object[clojure.lang.Namespace 0x… "user"] (the identity hash is
  elided).
- NA7. The core library is the subset the grammar uses, with core.jank's expansions and C++
  semantics. Core vars' metadata is simplified (:arglists, :doc, :jank/source {:module
  "clojure.core"}), except iteration's arglists (R131).
- NA8. A lookup in a namespace that does not exist should answer no-info (N2): Clojure's
  ns-resolve needs the namespace.

TB.set_of_bound, TB.deref_of_bound, TB.binding?_boxes — var::set/deref on a bound var.
TB.deref_set_same — var::set then deref of the same var gives the value set.
TB.deref_set_other — a var bound to another box is unchanged by var::set.
safeEval_success — for every value and every thread state with *1/*2/*3/*e bound to distinct boxes:
  *3←*2←*1←v, *e unchanged, result ok v. [new for every input]
safeEval_failure — for every thrown object, error_ref or std::exception: *e set to the returned
  exception, *1/*2/*3 unchanged. [new for every input]
safeEval_noForm_release — no form, release build: *1 = 0.0, result 0.0. [R132, every state;
  round 2: one scenario]
safeEval_noForm_debug — no form, debug build: the process aborts. [R132, every state]
jankDoEval_state_indep — do-eval's effect on the connection never reads the request map.
jankHandle_eval_session_indep — two evals differing only in their session leave the same process
  and connection state. [R127 for every input; round 2: found after 37 timelines]
outReply_nil_iff — do-eval sends no :out exactly when the output is C whitespace only.
  [R136 for every output; round 2: two scenarios]
evalString_analyzes_whole_form — whatever form the reader returns (a whole (do ...) included),
  eval_string's next step analyzes it as one unit. [N1, every form]
lookupTarget_unknown — a lookup whose ns names no namespace searches user. [N2, every state and
  name]

  preemptions from round robin". This made the two-connection searches complete; sdk's interleave
  decides at every step, so its trees cannot finish.
- Censuses with a prefix, and an IO census with a wall-clock deadline: a job prints "stopped at N
  (time limit)" before its alarm instead of dying silently.
- Exact tree partitions (partitionCensus: the all-zero timeline plus prefixes 0^i j), so a big tree
  splits into bounded jobs.
- Class labels by replay: on a mismatch, the timeline is replayed on spec variants that each adopt
  one known jank behavior, to name the class (also NA1 and R127 replays). Variants double as
  set-asides that keep the two processes from diverging.
- Mixed seeds (exploreMixed, SplitMix64) for every random run.
- Not a library gap but a pitfall noted: in this Lean version a structure instance's fields cannot
  end a line with a comma, and newline-separated fields must align.
