2. WHAT WAS MADE TERMINATING, AND THE RE-CHECK

- Jank/Lex.lean `next`, `lexNumber` (mutual `partial`): the bodies became the non-recursive
  `nextCore lexNum p0` (the number case passed in as `lexNum`; the only change in its text is
  `match lexNumber depth p tokenStart` → `match lexNum p tokenStart`) and
  `lexNumberCore den p0 tokenStart` (the denominator's lexer passed in: `if depth == 0 then return
  hang; let (den, p') := next (depth - 1) p` → `let some lexDen := den | return hang; let (den, p')
  := lexDen p`). `next` is structural in `depth`: `next 0 = nextCore (lexNumberCore none)`,
  `next (d+1) = nextCore (lexNumberCore (some (next d)))`; `lexNumber depth` = `lexNumberCore`
  with `none` at 0, `some (next (depth-1))` above (theorem `next_eq`). Names and signatures of
  `next` and `lexNumber` unchanged; new: `nextCore`, `lexNumberCore`, `next_eq`. (A
  well-founded version on (depth, rank) elaborated for over 4 minutes; the structural form
  compiles in seconds.)
- Jank/Read.lean `nextForm`, `wrap`, `parseUpto`, `parseColl`, `parseMeta`,
  `parseReaderMacro` (mutual `partial`): well-founded on (depth, rank) with ranks 3/1/1/2/1/2
  (and 0 for the new `nextFormBelow`).
  Every `nextForm (depth - 1)` became `nextFormBelow depth`, a new member of the block:
  `match depth with | 0 => pure (.crash "parser recursion never ends (stack overflow)") | d + 1 =>
  nextForm d`, which is what `nextForm 0` returns (its first line, before any state change).
  `jankEqual`, `jankSameKey` (`partial`): well-founded on the two values' sizes; the elementwise
  `(xs.zip ys).all` goes through `List.attach` (same values).
- Jank/Core/Destructure.lean: `Val.code`, `F.code` (a map's `fun (k, v) => …` → `fun kv => …kv.1…
  kv.2`), `valEq` (sizes; zip through `attach`), `eval`/`evalCall` (sizes; Lean's automatic attach
  through `mapM`), `evalE` (fuel, then term size; `if fuel == 0 then throw "fuel"` … `fuel - 1` →
  `match fuel with | 0 => throw "fuel" | fuel' + 1 => …` with the same arguments). New helper
  lemmas `sizeOf_fst_lt`, `sizeOf_snd_lt`, `sizeOf_zip_fst`, `sizeOf_zip_snd`.
- Jank/Core/Sorted.lean `cvEq`: well-founded on the first value's size; zip through `attach`;
  the same helper lemmas.
- Re-check: jank-reader rebuilt (Jank.Lex and Jank.Read recompiled from the new sources) and rerun
  (89 s): its 418 lines are identical to results/reader.txt (whose extra last line "exit 0" was
  written by round 2's run script, not by the exe). jank-core2 rebuilt (Jank.Core.Destructure
  and Jank.Core.Sorted recompiled) and rerun: identical to results/core2.txt except its timing

3. STILL PARTIAL OR UNPROVEN, AND WHY

- Destructure `pb`/`pvec`/`pmap` (still `partial`): `pmap` recurses on the entries `bes` that its
  `:keys`/`:syms`/`:strs` transforms build. Their keys are the binding map's keys or elements of
  its vector values, so they are subterms, but showing it needs an invariant through the
  `formAssoc`/`formDissoc` folds (and a measure that ignores the transformed values, which can be
  larger). Not done; `drawVal`/`drawBinding` (the search's generators) recurse on `depth - 1`
  guarded only by a one-option decision returning 0, so making them terminating means restructuring
  around `decide`; left as they are. Consequently the for-every-binding-form theorem is proved for
  the conversion (where jank's code differs from Clojure's), not for whole expansions: the rest of
  `destructure` is the same code in both flavors except gensym names. The conversion is proved on
  the runtime functions the expansion calls (`rtHashMap`, `rtMapConj`, `cljCreateAsIfByAssoc`);
  the same statement through `eval` of the two expansion forms (now possible, `eval` terminates)
  stops at simp evaluating the derived `BEq F` tests in `evalCall`; not finished.
- Lexer: `next` terminates; "no loop of `next` hangs on input without NUL" is proved for the symbol
  token (`lexSymbol_never_hangs`) and, for every loop, per iteration (`symF_spec`, `charF_spec`,
  `comF_spec`, `defF_spec`, `stringStep_next`) with the generic `flag_loop_done`; tying the eight
  loops of `nextCore` together (and `lexNumberCore`'s early returns) is not done.
- Parser: terminating; "reading returns a form or an error without NUL" is not proved. Note that
  `readAll` stops at 64 forms, so a NUL-free input with 65 forms "hangs" in the replica (a model
  bound, not jank).
- Array maps: the persistence theorem covers one transient and any sequence of its `assoc!`/
  `dissoc!`; the full world of round 1 (several maps and transients interleaved, `persistent!`,
  promotion, `check` over every map) is not proved.
- Sorted collections: only `cvEq` made terminating; no for-every-program theorem. The comparator
  pair `jankCompare`/`cljCompare` differs on R96–R99's classes, so such a theorem must be stated
  for keys on which the comparators agree.
- `Determinismo.linearizable` (sdk, `partial`) is not related to `Lin.Linearizable` by proof.

4. ASSUMPTIONS USED BY THE PROOFS

PA1. Linearizability is `Lin.Linearizable`: some order of a subset of the history's operations
     contains every answered (non-failed) one, respects real time (an operation answered before
     another was invoked comes first), and runs legally from the initial value with the
     acknowledged answers; an unanswered operation may be in it (any answer) or not (Herlihy–Wing
     with Jepsen's reading). It stands in for sdk's `Determinismo.linearizable`, which is
     `partial` (a search) and could not be reasoned about.
PA2. Atom fragment: clients run `swap! inc`, `@`, `compare-and-set!`, `reset!` and `add-watch`
     with a watch that only records (`WatchFn.record`); history ids distinct and ≠ 1000 (the id
     the replica gives a watch's nested `swap!`). Watches that call back into the atom (D16) are
     outside it. Any initial value, any number of threads and operations.
PA3. LL/SC: a weak compare-and-set may answer false without effect at any moment (C++
     [atomics.types.operations]: "may fail spuriously"); the weak register `weak` encodes exactly
     that; x86-64's `lock cmpxchg` never fails spuriously (the replica's `llsc = false`).
PA4. Deadlock means the replica's report (`interleave`: every live thread blocked); a run that
     reaches its decision limit ends normally.
PA5. delay: each thread derefs at least once before asking `realized?` (with none, `realized?` is
     false in both).
PA6. promise: "exactly one deliver returned the promise" is stated once every thread has ended
     (`maxSteps` can stop a run earlier; then "at most one" still holds).
PA7. Range: the fix is round 2's `countExact` (the count on exact integers); walks are compared
     for every number of elements taken.
PA8. P1's Clojure side is Clojure 1.12's APersistentMap.cons and PersistentArrayMap.createAsIfByAssoc
     as read in clojure-ref; jank's is base_persistent_map.cpp as read at 7135b7708 (not run).
PA9. Lexer: "without NUL" means every byte of the file is non-zero; either locale.
PA10. Multimethods: the replica's `prefers` walks at most 16 levels (round 2's fuel); the theorems
     compare jank's and Clojure's replicas with that same walk.

5. PROPERTIES PROVED (for every input of the stated fragment)

- Atoms (target 1): every interleaving's history is linearizable against the register, on x86-64
  and in the Clojure mode, for any number of threads and operations; on LL/SC against the register
  with a weak compare-and-set, and against the strong register when no `compare-and-set!` is used
  (spurious failures only make `swap!` retry); round 1's LL/SC tape gives a history the strong
  register cannot explain (D17). With recording watches the run never deadlocks (D16 needs a
  watch that calls back).
- Multimethods (target 2): without preferences (round 2's theorem, every input); with any
  preferences when every method is on a parentless tag; in general whenever jank's and Clojure's
  dominance agree on method tags; jank's preference walk is exactly the direct lookup (R100).
- Destructuring (target 3): the kwargs conversion agrees with Clojure for every argument list
  whose trailing element (odd count) is not a seq of entries or `()`; P1 found on the way.
- Vectors (target 5): every index law, including when `nth`, `assoc`, `pop`, `subvec` throw and
  what `subvec` returns; transient `nth` answers as Clojure's for every transient and index.
- Array maps (target 5): after the clone fix, any sequence of `assoc!`/`dissoc!` on
  `(transient m)` leaves `m`'s entries unchanged, for every array map.
- delay/promise (target 5): a delay with a value body (and the Clojure mode, any body) runs once
  and is realized after a deref, any threads and derefs; at most one `deliver` returns the promise,
  exactly one once all threads ended.
- Lexer (target 6): every successful decode of a non-NUL byte advances; every loop iteration
  stops or advances inside the file; the symbol token never reports a hang without NUL.
- Integer range with the exact count (target 7): Clojure's elements and ending for every i64
  start, end, step, in the 1-, 2- and 3-argument forms.
