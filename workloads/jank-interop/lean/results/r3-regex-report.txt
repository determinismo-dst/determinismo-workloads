RX13. Matching recurses per character: long inputs overflow the stack (SIGSEGV). (new; property)
  (re-find #"a*" (apply str (repeat 3000000 \a)))   ; Clojure "aaa…"   jank: crash
  Depth of _M_dfs (replica, measured n = 10…3000; exact linear fits): a*, .*, [^,]*: 2n+4; \w+: 2n+3; a*?$: 2n+5;
  (?:ab)*: 1.5n+4; (a)*: 4n+4; (a|b)*: 5n+5; (?:a|b)*?c: 3n+5. Almost every frame is a non-tail call
  (_M_rep_once_more's dfs(alt) and _M_handle_match's dfs(next) restore state after the call), so sibling-call
  optimisation does not remove them (NT ≈ D in results/r3-regex.txt).
  Stated bound: with an 8 MiB stack and ≥ 16 bytes per non-tail frame (RXA4), depth > 524,288 frames overflows:
  a*-shaped patterns at n ≥ 262,143 matching characters; at a more realistic ≥ 64 bytes per frame, n ≈ 65,000.
  Java matches single-character repeats in a loop (no per-character recursion).
  Path: regex_executor.tcc _M_dfs 510, _M_rep_once_more 178, _M_handle_match 321. Reach: any re-find/re-matches/
  replace/split over a long run of characters matched by a repeat. Confidence: high on the recursion and its slope;
  the byte bound rests on RXA4.

- The executor theorems run in the kernel only for tiny programs (decide +kernel).

  — all confirmed by the replica; "regex_iterator not modelled" — now modelled.
Standing / new:
- RXA1: glibc gives bytes 0x80–0xFF no class in the C locale (C-ctype.c) and in a UTF-8 locale (not single-byte
  characters of the charmap); ASCII classes and tolower are the same in both. So the two locales give the same
  answer to every regex question (all tables were run in both: identical). The locale only decides whether non-ASCII
  text reaches a regex (R22).
- RXA2: in a named locale, transform_primary (collate<char>::transform after tolower) is equal exactly when the
  lowered single characters are equal (only [[=x=]] uses it).
- RXA3: x86-64 (signed char). On aarch64-linux char is unsigned: RX3 would vanish and ranges like [\x80-\xff] change.
- RXA4: the main thread's stack is 8 MiB (no stack size is set in jank: no setrlimit/pthread_attr in the tree), each
  non-tail _M_dfs frame takes ≥ 16 bytes, and GCC does not inline _M_dfs into itself.
- RXA5: jank on Linux links libstdc++ 15.3.0 (nixpkgs pin); a macOS build (libc++) is not covered.
- RXJ1: JDK ≥ 19 (\b uses ASCII word characters, like \w).
- RXJ2: Java's loop rule: an iteration of a quantified group that matches empty ends the loop (Loop/LazyLoop/Curly).
- RXJ3: Pattern corners the javadoc does not state: dangling ']' '}' literal, a leading ']' in a class literal,
  '{' with nothing before it repeats an empty atom, \b{x} for x ≠ g is \b then '{'.
- RXJ4: captures inside lookaheads: compared through the whole match only.
