3. LEFT OUT, AND WHY
======================================================================
- folly spin/yield phases and applyDeferredReaders' spin phase (only delay; folded into the futex path / forced path, RTA1-RTA2); try_lock*/timed variants and token-less lock_shared (unused by jank); reader-priority instantiation (unused).
- Synchronized::copy/swap/withRLock/withWLock/contextualLock: no uses in jank (grep); copy/swap semantics read from Synchronized.h 943-946 (copy under ConstLockedPtr) and 896-907 (swap locks both exclusively in address order).
- The JIT interpreter recursive mutex (jit/processor.hpp 102): held only around Clang calls and declarations (processor_dynamic.cpp 362-735, cpp_util/cppinterop), no jank callbacks except user cpp/raw code; multi_function's recursive mutex: no callbacks under it (dispatch and methods run unlocked); its method_cache read in get_fn without the lock (a word-sized race; Clojure uses a rwlock) noted, not modeled; lazy_sequence/range recursive mutexes match Clojure's synchronized (round 1).
- native_array_blocking_queue, codegen/JIT object Synchronized maps: compile time, no jank callbacks.
- bdwgc internals beyond reachability (block allocation, free-list reuse, parallel marking, black-listing): a freed object is reported at its next use, without modeling reuse. Incremental mode: on Linux bdwgc uses SOFT_VDB (gcconfig.h 1256-1257, 2141-2142; kernel soft-dirty bits) so no client write barrier is needed; not searched further.
- The two-thread lock census uses 12 of the 21 operations (alphabet2) and bodies of one operation chosen for the top level only; 143 of 37,488 programs exceeded the 20,000-state bound (class "(search stopped)", mostly validators that swap! the atom beside a future) and are undecided.
- macOS: futures are not registered (core.cpp 1109-1121) on the claim that bdwgc does it; not modeled (RTA9).

4. ASSUMPTIONS
======================================================================
Replaced:
- Round 1 A7 ("wlock() is two steps: announce, which blocks new readers, then acquire") → folly's: lock() sets kHasE only once no kHasE/kBegunE/kHasU is set, then drains readers; a writer still waiting for another writer blocks no reader; deferred readers count as readers. Confirmed for deadlocks: on all 108 S/E programs of the table, round 1's lock (= Determinismo.RwLock with writer priority) deadlocks exactly when the replica does; round 1 has no upgrade mode.
- Round 1 "folly's SharedMutex is non-reentrant and gives writers priority (SharedMutex.h 1421)" → confirmed by the replica (refinement table, theorems).
- Round 2 RC "folly fbvector has null storage when empty" → refined: b_ = e_ = z_ = nullptr for a vector that never allocated (Impl 98-104, init(0)) or after shrink_to_fit of an empty vector (983-987) or a move; clear()/erase/pop_back keep the block (1146), so data() of such an empty vector is non-null and data()[0] is a stale element, not a null read (affects only the wording of round 2's native_vector_sequence::first note).
New:
- RTA1. Spinning in waitForZeroBits and sched_yield phases are loads that only delay; the futex loop's own load stands for them.
- RTA2. applyDeferredReaders: its forced path (load and CAS every slot) stands for the spin-then-force path.
- RTA3. getMaxDeferredReaders() = 2 or 4 (both run); AccessSpreader::current is a decision; futexWake(1) wakes any eligible sleeper (decision); no spurious futex wakeups.
- RTA4. The jank-level searches use the coarse lock CSM, justified by the refinement table (1,360 programs, both slot counts, 0 mismatches); every finding was re-run with the fine replica (all confirmed except the validator-swap!-beside-set-validator! variant, stopped at 500,001 fine states; its sibling with get-validator is confirmed).
- RTA5. Callback bodies run at a depth budget; at depth 0 a callback does nothing, in jank and Clojure alike (Clojure's StackOverflowError on a self-deref is reported from the docs, not modeled).
- RTA6. Clojure's var metadata expression is compared as if run lock-free at first read (its timing is R43's matter).
- RTA7. pthread_cancel acts only at (sleep); unwinding releases the guards still held; std::thread::join on itself throws (EDEADLK) and unwinds to the future's catch handlers.
- RTA8. GC: a collection may run at any allocation of any thread; conservative scanning finds no stale copy of a dead frame's pointers; malloc memory (incl. the C++ runtime's exception objects) is never scanned (no REDIRECT_MALLOC in jank's bdwgc build).
- RTA9. Linux: future threads register (core.cpp 1111-1115); the macOS path is not modeled.
- RTA10. Module-target lifted globals are laid out in declaration order (the GC_add_roots(&first, &last + 1) ranges, cpp_processor.cpp 2120-2170, then cover them; reversed order would leave them unrooted — counterfactual found after 2).
- RTA11. persistent_string layout: vptr 8, object_type u8 at 8, object_behavior u16 at 10, data at 16 (storage 24 bytes + u32 hash, 32 bytes): 48 bytes, 6 words.
