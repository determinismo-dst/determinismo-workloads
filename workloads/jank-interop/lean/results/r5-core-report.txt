#inst (Jank/R5/Core/Inst.lean): each single-input fact is a kernel-checked theorem (decide +kernel over
the replica; `chars%` gives the kernel a List Char): z_rejected, z_clojure, leap_rejected, leap_clojure,

tag dispatch differ exactly when the tag is built in, not mapped, and the default fn is set (G7). The
census is complete over its alphabet; no for-every-string theorem was attempted for the parser.

CHAMP laws beyond get-after-add (Jank/R5/Core/ChampLaws5.lean, ChampWf5.lean), over round 3's replica of
immer's champ.hpp, for every champ satisfying round 3's wfNode, every hash function and every equality,
with only the link between the query and the value (`hashK k = hashT v`, `eqTK x k = eqTT x v` for
every x: true of jank's mapCfg/setCfg by construction):
- ★ added_doAdd: do_add's `added` flag is exactly "get along the same hash found nothing", at every
  level, collision nodes included. ★ size_add: (count (assoc m k x)) = (count m) + (if (get m k) is
  nil then 1 else 0); the same for conj on sets.
- ★ added_doAddMut, ★ size_addMut: add_mut (assoc!/conj!) sets the same flag on every branch (in place
  when the node is owned, through do_add when not), so the transient count equals the persistent one.
- ★ doSub_absent, ★ sub_absent: dissoc/disj of a key get does not find returns the same champ and
  allocates nothing; ★ doSubMut_absent, ★ subMut_absent: the same for dissoc!/disj!, on the mutating and
  the copying branch.
- ★ doSub_found, ★ size_sub: dissoc/disj of a key get finds returns a tree (never the root "singleton"
  immer marks unreachable), so the count drops by one.
- ★ makeMerged_wf, ★ doAdd_wf, ★ add_wf, empty_wf: add keeps wfNode, and the empty champ has it, so the
  premise of every law above (and of round 3's get_add) holds for every champ built by adds from empty.
- ★ size_add_add, ★ get_add_add: adding the same value twice changes neither the count nor get.
- ★ doSub_ok, ★ get_sub (ChampSub5.lean): after dissoc/disj of k, get of k finds nothing, for every
  well-formed champ holding at most one value Equal to k. doSub_ok follows do_sub through each case: a
  collision node shrunk (the rest holds nothing Equal to k) or collapsed to the value left; a data slot
  removed; a two-value node collapsed, its other value passed up (never Equal to k) and inlined by the
  first ancestor that keeps other entries, into the slot of k's bit; the root's own collapse; empty().
  The premise is the law's: with two stored values both = to k (D12 lets 1 and 1N sit in one hash set,
  each = to 1), removing one leaves the other.
- ChampR55.lean (G11 on the replica): with an equality false for one value, adding it twice to an empty
  champ stores it twice (r55_stored_twice) and get never finds it (r55_never_found); the control value
  is stored once (control_stored_once).
What these make complete: the bounded CHAMP searches of rounds 3-4 (M4-2, M4-3, M5, S3-3) checked count
and lookups only up to 3-4 steps; for count after add/remove, remove of an absent key, the transient
count, and add idempotence they are now proved for every length.
Not proved (and why): get of another key after add or remove, and "iteration yields each key once and
exactly the keys present" (hence get_sub's premise for champs built by adds). These need a hash-path
invariant (every stored value sits on its hash's path, do_check_champ) carried through make_merged, the
inline/collapse cases of do_sub and the collision node's reordering, plus an equality that agrees with
the hash; jank's does not (D12, R55), so they hold only on a restricted key domain. They stay covered by rounds 3-4's complete bounded searches
over longs (hash-consistent: M4-2 complete 61,642; S3-3 complete 838,319; M5 transients complete
7,572,128), with nothing found. The transient's structure (not just its count) agreeing with the
persistent one is likewise searched (M5), not proved.
