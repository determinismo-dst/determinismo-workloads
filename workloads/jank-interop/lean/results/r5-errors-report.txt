(4) STILL LEFT OUT, AND WHY
======================================================================
- The printed report (error/report_dynamic.cpp: snippets, notes, ellipses, colors): text for a human,
  with no Clojure counterpart (Clojure prints clojure.main/ex-triage's message). Read, not modeled.
- Positions. jank names the offending token's own position (e.g. an unresolved symbol:
  processor.cpp 1693–1696, meta_source of the symbol); Clojure names the innermost enclosing list's
  (analyzeSeq 7604–7615 binds LINE/COLUMN from the list's meta; analyze wraps the exception with
  them, 7634–7640; at a file's top level a bare symbol gets 0:0). So for `(foo nope)` on line 1,
  jank's report says 1:6, Clojure's ex-data 1:1. A different rule, not a defect (jank's is the more
  precise), and in jank the position is not data a program can read (B1, B12): it is only in the
  report text. Token positions themselves agree (round 4's ★ jankPos_eq_cljPos). Not searched.
- A thrown value of a foreign native type (neither object, std::exception nor error_ref): reachable
  only through cpp/raw code; load_module lets it through, safe_eval's last handler catches it.
- throw of a non-exception value (allowed by jank's book, a ClassCastException in Clojure) and
  (catch :default e …) (jank binds nil; Clojure has no :default): by design, noted by round 4.
- evaluate.cpp eval(def) 348–353 sets the thread-local current_def_var and resets it only after the
  value's eval returns; an exception in between leaves it set, and a later top-level bare fn would
  rebind that var at its first call. No user-reachable trigger was found (the fn's metadata is a
  constant map, analyze_fn 2063–2066; gen_cpp's throws are internal failures), so it is a note.

(6) PROPERTIES CHECKED, WITH THEIR SOURCES
======================================================================
- An error a Clojure program can catch can be caught by jank's object handler (Clojure: try/catch of
  Throwable, special_forms "try"; jank's book cpp-interop/native-exceptions.md: values thrown from
  jank are caught as object_ref).
- The root cause's data is reachable through ex-cause (core.clj ex-cause/ex-data docstrings;
  CompilerException's cause, Compiler.java 7381).
- A failed require leaves no namespace it created (core.clj load-lib 5999–6007).
- A delay runs its body once and rethrows the same exception (delay docstring "will invoke the body
  only the first time it is forced"; Delay.java).
