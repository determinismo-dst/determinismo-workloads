H1 (extends D12; corrects D12's third example). An equal key with another hash is found or not
    depending on unrelated elements: an unrelated conj or disj flips contains?, get, disj, count
    and set =.
    (let [z (id 0.0) nz (id -0.0) two (id 2.0) s1 (hash-set z) s2 (conj s1 two) s3 (disj s2 two)]
      [(contains? s1 nz) (contains? s2 nz) (contains? s3 nz)        ; jank [true false true]
       (count (disj s2 nz))                                         ; jank 2
       [(count (conj s1 nz)) (count (conj s2 nz))]                  ; jank [1 3]
       (get (hash-map z :a two :b) nz)                              ; jank nil
       (= (hash-set z two) (hash-set nz two))])                     ; jank false
      Clojure 1.12.0: [true true true] 1 [1 2] :a true.
    Why: 0.0 and -0.0 are = (number.cpp real::equal 267-282, small_real::equal 385-400; tagged
      reals oref.hpp equal 402-436: C++ ==), but hash::real (hash.cpp 116-127, v ^ (v >> 32) of the
      bits) gives 0 and 2^31. These share their low 30 bits, i.e. the chunks of CHAMP levels 0-5.
      immer's get (champ.hpp get 537-) walks the QUERY's hash 5 bits a level and compares the
      first data slot it meets (Equal{}(stored, query) = runtime::equal, core/equal.cpp 19-22). In
      #{0.0}, 0.0 sits at the root's slot 0 and -0.0 reaches it. 2.0 (hash 2^30) has the same six
      chunks as 0.0, so conj 2.0 runs make_merged (champ.hpp 609, node.hpp 993-1019) down to level
      6, where 0.0 takes slot 0, 2.0 slot 1 and -0.0 asks for slot 2: not found. disj 2.0 collapses
      the chain (do_sub 1206-1276: the singleton passed up and inlined at the root) and -0.0 finds
      0.0 again. 1.0 (hash 0x3FF00000) splits from 0.0 at level 4 where -0.0 still agrees with 0.0,
      so (contains? (hash-set 0.0 1.0) -0.0) is true. hash-set/hash-map build CHAMPs at every size
      (persistent_hash_set.cpp create_from_seq 45-53, conj 149, contains 186, disj 191;
      persistent_hash_map.cpp get 74/84, assoc 110, dissoc 116; set = calls contains, 55-81).
      Transients the same (transient_hash_set.cpp conj_in_place 43, disjoin_in_place 103; champ.hpp
      do_add_mut 645-, do_sub_mut 1346-).
    Correction: round 1's D12 lists (contains? #{0.0} -0.0) as false on jank. Round 1 abstracted
      immer as "same full hash and equal" (Jank/Equality.lean containsH); round 3's CHAMP replica,
      run with round 1's own values (jank6-champ show), says true: D12's third assertion would
      PASS on jank. (D12's test failed on its first assertion, so the third never ran; nothing
      confirmed is contradicted.) Round 5's "(disj #{0.0 2.0} -0.0) keeps 0.0" is right and is one
      side of H1.
    Law broken: law 1 (get of another key after add / after remove), both directions, and with it
      law 2 against Clojure (the keys iteration yields are Clojure's, but get/contains? of an =
      key disagrees with them, and count after conj of an = key depends on the path).
    Theorems: Breaks.negzero_compat_fails, negzero_found_alone, negzero_lost_after_add,
      negzero_found_after_sub, negzero_found_with_one, negzero_disj (kernel-checked on the replica).
    Tests: vH1-an-unrelated-element-hides-an-equal-key (persistent, values through a fn),
      vH1b-a-transient-hides-an-equal-key-too (transient conj!/disj!).
    Status: extends D12 (same cause: hash::real hashes -0.0 apart from 0.0; one fix: hash -0.0 as
      0.0, as Clojure's Numbers.hasheq does); corrects D12's third example. Confidence: high (the
      replica is round 3's, cited line by line; the walk below and the kernel facts agree; the
      Clojure side ran).

H2 (extends V48: another value, another cause). The same ##NaN object is never found, is stored
    twice, and is never removed.
    (defn f [x] [(contains? (hash-set x) x) (count (hash-set x x)) (get (hash-map x 1) x)
                 (count (disj (hash-set x 3) x)) (= (hash-set x) (hash-set x))])
    (f ##NaN)   Clojure [true 1 1 1 true]   jank [false 2 nil 2 false]
    Why: ##NaN is jank_nan, a tagged small_real (read/parse.cpp 874-876, number.cpp 512);
      runtime::equal on two tagged reals is C++ == (oref.hpp 414-419), false for NaN, and immer's
      Equal (std::equal_to<object_ref> -> runtime::equal) has no identity test. Clojure's =
      is also false on NaN, but PersistentHashSet/Map compare keys with Util.equiv, whose first
      test is k1 == k2 (the same object). do_add finds no Equal value, so the two copies (same
      hash) go through make_merged to one collision node at the last level; get and do_sub never
      match. count and (count (seq s)) agree (2): see 2's count_eq_seq_*.
    Test: vH2-a-set-finds-its-own-nan (value through a fn, so Clojure's side is one boxed object;
      with a let-bound primitive double Clojure boxes twice and also gives false/2).
    Status: extends V48 (V48: a value jank finds unequal to itself, (seq "é"), via R55). The CHAMP
      consequence is the same (Breaks.nan_stored_twice, nan_never_found = R5's r55_stored_twice
      for this value); the cause differs: jank's (= ##NaN ##NaN) agrees with Clojure, the
      missing identity shortcut in the collections does not. A fix for R55 does not fix H2; an
      identity test in the champ's equality (or runtime::equal) fixes H2 and masks V48.
    Confidence: high.

Shared causes: H1 shares D12's (hash::real); H2 shares V48's CHAMP path but not its cause. H1 and
H2 are separate.

  1N: 2654435770 & 31 = 26), so the miss is static at every size: D12 as stated.
- Asymmetric = (R55: (= (seq "é") v) false while (= [\é] (seq "é")) compares by elements) and
  BigDecimal's non-transitive = (D8): reachable only together with R56/D8's hash differences;

- count vs (count (seq s)): never differ, for every hash and equality (proved, 2), so no program
  sees them disagree through conj/disj/conj!/disj!.
- "a collision node keeping two equal keys": impossible unless = is not reflexive (H2/V48); under

  reads, so D12 pairs never meet there.
- "disj removes the wrong one": disj removes the value its walk finds Equal; with D12 that may be
  the =-key's twin (Clojure would remove it too) or nothing (H1); never a value not = to the key.

2. PROOFS (no sorry, no native_decide, no new axiom; axioms in results/r6-champ-axioms.txt)
======================================================================
Over round 3's replica of immer's champ.hpp (Jank/R3/Immer/Champ.lean), for every node that
satisfies round 3's wfNode.

The hash-path invariant (Ops.HP): in every inner node r+1 levels above the collision level, the
value in bit d's data slot has d as its hash's chunk at that level (idxAt h (65 - 5(r+1))), every
value under bit d's child has d there too, recursively; collision nodes only at the last level
(wfNode). So every value sits at the path its hash's chunks name, and two values in one collision
node agree on the 65 bits get reads.

For every hash function and every equality (nothing assumed):
- ★ Slots.getLoop_walk: get k = find? (Equal · k) of the list the walk on k's hash reaches.
- ★ Slots.iter_slots / iter_split: a node's iteration is (up to order) its 32 slots' values.
- ★ Slots.edit_* (8 lemmas, one per node.hpp constructor: copy_inner_replace, _replace_value,
  _insert_value, _replace_merged, _replace_inline, _remove_value, the root collapse, empty()):
  the result is well formed and differs from the source in exactly one slot.
- ★ Ops.add_step: do_add keeps wfNode and HP; its iteration is the old one with v added (added) or
  with one stored value Equal to v replaced by v (not added).
- ★ Ops.sub_step: do_sub returns nothing; a value passed up from a subtree holding exactly it and
  one value Equal to the key; or a tree that keeps wfNode and HP and iterates as the old one minus
  one value Equal to the key. Every collapse case: collision node shrunk / collapsed to one value,
  data slot removed, two-value node collapsed and inlined by the first ancestor that keeps other
  entries, the root's two-value collapse, empty().
- ★ Mut.addMut_step, ★ Mut.subMut_step: the same for do_add_mut and do_sub_mut on every branch
  (in-place child write, in-place value write after ensure_mutable_values, in-place collision write
  (which keeps the collision order where do_add moves v to the front), moves, copies, owner tokens).
- ★ Ops.HP_makeMerged, wf_makeMerged, iter_makeMerged (with or without an owner).
- ★ Laws.count_eq_seq_add, ★ count_eq_seq_sub: count (immer's size) = the iteration's length after
  add/sub, whatever the equality: (count s) = (count (seq s)) for every champ built by conj/disj.
- ★ Laws.walk_complete, get_sound, get_complete: under HP every stored value is on its own hash's
  walk; get only returns stored values Equal to the key.

For every equality that is an equivalence compatible with the hash (Laws.Lawful: Equal reads one
key per value (Prod.fst for maps), refl, symm, trans, Equal keys hash alike):
- ★ Laws.inv_add, ★ inv_sub: well formed, HP, no two stored values Equal, size = iteration length.
- ★ Laws.get_iff: get k = some x iff x is stored and Equal to k (so get_sub's premise "at most one
  stored value Equal to k" holds for every champ built by these operations).
- ★ Laws.get_add_other, ★ get_sub_other (law 1): get of a key not Equal to the one added/removed
  is unchanged.
- ★ Laws.keys_add, ★ keys_sub, ★ build_keys, ★ build_from_empty (law 2): for every sequence of
  add/sub from champ::empty(), iteration yields each key once and exactly the keys Clojure's model
  holds (present iff the last add/sub naming an = key was an add).

What these make complete: rounds 3-5 searched get of other keys and iteration only to 3-4 steps
(M4-2 complete 61,642; S3-3 complete 838,319; M5 7,572,128); they now hold for every length, under
Lawful. Round 5's get_sub premise is discharged.

What did not close / was not done:
- get_add_other and get_sub_other are stated for champs meeting the invariant (Inv: HP and
  uniqueness), i.e. every champ built by these operations, not for an arbitrary wfNode champ. A
  direct walk-based proof of get_add_other for every wfNode champ (which needs no HP, only Lawful)
  was planned, not written.
- The sequence theorem (build_keys) covers persistent add/sub. addMut_step/subMut_step give the
  transient steps the same invariants (wf, HP, iteration), and R5's added_doAddMut ties add_mut's
  flag to get; a sequence theorem with transient steps also needs "do_sub_mut of a key get finds is
  never nothing" (R5 proved it for do_sub only), not written.
- Transients agree with the persistent ops as multisets of values (both meet AddOut/SubOut); the
  node-by-node shape (collision order) differs and is not compared.
