-- D9 (fixes/D9.diff) --------------------------------------------------------------------
File: include/cpp/jank/runtime/oref.hpp, detail::tag(f64) (193-197).
Change: a double whose bits are >= max_real (a negative quiet NaN; x86-64's default NaN
0xFFF8'0000'0000'0000 from inf-inf, 0/0, 0*inf) is stored as std::numeric_limits<f64>::quiet_NaN()
(0x7FF8...). Every other double is stored as before.
Why safe: those bit patterns are the tag space (0xFFF9 ints, 0xFFFA pointers, the rest decodes as
nothing), so no correct value is lost; only the NaN payload/sign changes, which nothing observes
(NaN prints ##NaN, `=` is false either way). One compare-and-branch per boxing of a real.
Read-checked: tag(f64) is the only path from a small_real to an object_ref: oref<object>'s
constructor from oref<small_real> (280-289) and oref<small_real>::erase() (2303) both call it;
make_box(f64) returns oref<small_real> (make_box.hpp 79-85); no other bit_cast stores a double
in an oref (grep); math.hpp sub/div box their f64 result with make_box. cpp_processor 195 reads
a tagged real back with as_real, after tagging.
Test: d09-nan-from-infinities, d09b-nan-from-zero-over-zero (no more segfault).
Note on the tests (they are wrong against Clojure 1.12, though round 2 reported them passing on
Clojure 1.11.1): Clojure 1.12 gives false for d09's `(let [x (sub ##Inf ##Inf)] (not= x x))`
(Util.equiv's identity check on the one boxed Double), and throws ArithmeticException "Divide
by zero" for d09b's `(div 0.0 0.0)` (Numbers.divide through Object params checks a zero
divisor). With D9, jank gives true for d09 (small_real equal is NaN == NaN, false, and jank's `=`

Clojure does not. A sound test of D9: `(let [x (sub ##Inf ##Inf)] (is (NaN? x)))`. jank's

-- D24 (fixes/D24.diff) --------------------------------------------------------------------
File: src/cpp/jank/codegen/cpp_processor.cpp, gen(try) (1054-1100).
Change: with a finally, the generated C++ is now
  { finally-lambda; scope_exit guard; try { try { body } catch(T e) { handler } }
    catch(...) { guard.release(); finally(); throw; } guard.release(); finally(); }

the old output exactly. Without a finally the output is unchanged.
