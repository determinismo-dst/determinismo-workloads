Round 6, area P: native values (exe jank6-native). jank main 94d32623 (upstream-r5/), Clojure 1.12.0.
Every jank path is upstream-r5/compiler+runtime/<path>. Every item is a hypothesis from a Lean replica,
re-read against the source; jank was not built or run.

How a native number reaches a Clojure operation (the mechanism behind every item):
- The analyzer types number and boolean literals natively: an integer literal is `int` when it fits 32
  bits, else `long` (analyze/cpp_util.cpp literal_type 602-648); a double literal `double`; true/false
  `bool` (R25, R33).
- A call of a var with `:inline` metadata is replaced by the inline fn's form before analysis
  (analyze/processor.cpp analyze_call 3536-3567). core.jank's inlines (146 `:inline` keys) reach C++:
  - natives returned: count -> sequence_length: usize = unsigned long long (core.jank 185-192, seq.hpp
    132, seq.cpp 837-879); alength -> usize (6021-6027, array.hpp 88-100); hash -> to_hash: uhash =
    unsigned int (2479-2486, core.hpp 87, core.cpp 623-626); int -> to_int: i64 = long long (202-208,
    math.hpp 1409-1436); float -> to_real: f64 (211-217, math.hpp 1438-1464); boolean -> truthy: bool;
    every predicate (nil? empty? true? false? not some? seq? coll? vector? zero? pos? neg? even? odd?
    integer? float? boolean? number? contains? == < <= > >=): bool; bit-and/or/xor/not/... -> i64
    (math.hpp 1391-1402); aget of a typed array -> T& (array.hpp 32-36) since byte-array, int-array,
    float-array, char-array ... are themselves inlined and return typed array_refs (6620-6730).
  - templates that take natives: + - * / -> add/sub/mul/div (1372-1435), < <= > >= -> lt/lte (with `>`
    swapping operands, 1552-1615), min/max (1616-1645), inc/dec (1646-1662), abs (1817-1826), zero?
    (is_zero); int/float (to_int/to_real).
  - everything else (=, compare, quot, rem, ==, pos?, neg?, even?, nth, get, ...) takes object_ref: a native
    argument is boxed first (convert<T>::into_object, convert/builtin.hpp 225-245: make_box(static_cast<i64>(o))).
  - long, double, char, compare, mod, num are plain defns (5768-5799): their results are boxed objects.
    byte, short and the unchecked-* casts throw "TODO: port" (U74's class).
- A cpp_call's type is the return type of the overload Clang picks (processor.cpp build_cpp_call 525-690,
  get_function_return_type); the code generator writes `auto t(<literal text>);` for a literal and
  `auto &&t(jank::runtime::lt(a, b));` for the call (codegen/cpp_processor.cpp 1278-1285, 1352-1440), so
  C++ resolves the template again on the C++ types of the temporaries. A `let` local keeps the value's native
  type (processor.cpp 2370-2420); a `loop` local keeps it too (cpp_util.cpp mutable_type 1064-1090).
- In core/math.hpp each binary op has four templates selected by detail::primitive_number<T>
  (std::is_integral_v || std::is_floating_point_v, 28-29: bool and char count). The both-primitive template
  applies C++'s operator with the usual arithmetic conversions (add 172-178, lt 622-628, div 400-406); min/max
  convert both to std::common_type and call std::min/std::max (856-863, 983-990); a primitive meeting an object
  computes `l op typed_r->data` with the object's data (i32 for a small integer, i64 for an integer, f64 for a
  real; exact for ratio/bigint through ratio.hpp's integral templates and boost) (lt 566-620, min 790-854).
- The fn-value path (apply, a local bound to the fn, a defn wrapper) boxes every argument before the fn body
  runs the object-object template, so no native operand reaches math.hpp there.

(2) PROOFS
For every input (Jank/R6/Native/Theorems.lean, bv_decide on BitVec 64 / 32):
- lt_i64_usize_differs_iff, lt_usize_i64_differs_iff: for a count a < 2^63 and any i64 b, C++'s unsigned `<`
  differs from the numbers' `<` exactly when b < 0 (both operand orders).
- le_differs_iff: the same for `<=`.
- lt_int_usize_differs_iff: an int literal, sign-extended: the same set.
- min_differs_iff, max_differs_iff: std::min/max over unsigned long long, boxed as i64, differ from Clojure's
  min/max exactly when the other operand is negative.
- div_usize_by_i64_differs_iff: (/ a b) differs from truncating division iff b < 0 and -b <= a (unsigned).
- div_i64_by_usize_differs_iff: (/ b a) differs iff b < 0 and a >= 2.
- add_usize_exact: + on the same bits read as i64 is exact when no signed overflow (so + - * with a usize
  operand only go wrong when the result is consumed natively again, P1e).
- hash_boxed_eq_iff: a u32 boxed as i64 equals Clojure's signed int hash iff its top bit is clear.
- hash_sub_one_wraps: (- (hash 0) 1) is 4294967295 in u32.
Kernel-checked facts about the model's C++ (Types.lean, decide): uac_unsigned_wins (every unsigned type of rank
>= int against every signed type of no higher rank converts to unsigned, both orders), uac_signed_survives,
uac_ullong_int/long/llong, uac_uint_int, uac_uint_llong, uac_uchar_int, uac_bool_int, commonType_*.
Not proved: the walk's other cells (they mix Floats, which Lean cannot decide; searched instead); that jank's
hash::integer equals Clojure's Murmur3.hashLong (read side by side; the model has one definition, checked against
the JVM's values); Clang's overload choice among the four templates (read: the both-primitive template's
constraint subsumes the others').

(4) NOT EXACT
- Floats are Lean's binary64 (and Float32 for float values); results printed with 17 significant digits cut,
  not Clojure's shortest form.
- Ratio and bigint operands are modeled in comparisons and min/max only (arithmetic with them is not walked).
- Typed object refs (oref<integer> arguments) are not sources: only literals' boxed constants produce them.
- The `char` signedness is x86-64's; on AArch64 Linux a char array element above 127 differs.
- Clojure's static types are modeled only where they change a result (Numbers.divide's zero check).
