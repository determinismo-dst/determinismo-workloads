How a Clojure arithmetic form reaches math.hpp (what everything below rests on; read, not assumed):
- `+ - * / < <= > >= min max` with two arguments inline to `cpp/jank.runtime.<op>` (clojure/core.jank 1371-1434,
  1566-1660, `:inline-arities #{2}`); `inc dec zero? pos? neg? quot rem abs int float ==` inline too; `-'`, `+'`,
  `*'`, `inc'`, `dec'`, `long`, `double`, `bigint`, `bigdec`, `compare`, `=` never do. Other arities run the defn.
- A long literal is a C++ `int` when it fits i32, else a `long` (analyze/cpp_util.cpp literal_type 630-643, 652-658),
  emitted as `auto tN(<digits>);` (codegen/cpp_processor.cpp gen(cpp_literal) 1278-1285, lift_constant 131-149).
  A double literal is a `double`; BigInt, ratio and BigDecimal literals are `object_ref`s.
- A let-bound local keeps its init's C++ type (analyze/processor.cpp analyze_let 2370-2421; a loop binding too,
  mutable_type 1064-1089 erases only typed objects).
- A fn parameter or any value passed through a fn is an `object_ref`: a `small_integer` (i32 data) when it fits i32,
  else an `integer` (i64), by make_box (core/make_box.hpp 89-101; visit.hpp visit_number_like 463-498).
- The literal -9223372036854775808 is a `big_integer` (round 2's R5: read/lex.cpp 1143-1157, strtoll of the digits
  after `-` gets ERANGE).
- math.hpp computes `l OP r` in the operands' C++ types: int OP int is 32-bit, anything with a long is 64-bit, both
  wrapping (-fwrapv); `inc`/`dec` check with __builtin_*_overflow (math.hpp 1186-1340).
- Clojure: two primitive longs (literals or let-bound literals) call Numbers.add/minus/multiply(long, long) =
  Math.addExact etc. ("long overflow"); any Object operand calls the Object overloads (Numbers.java 154-178), where
  `minus(x, y)` is `add(x, negate(y))` and `negate(Long/MIN_VALUE)` throws.

(2) Proofs
----------
For every input (Lean, Jank/R6/Num/Int.lean; omega and the BitVec toInt lemmas; no bv_decide needed):
- ★ cpp_int_op, cpp_long_op, cpp_int_long_op: C++ `int OP int`, `long OP long` and `int OP long` with -fwrapv
  (BitVec 32/64, sign extension) are `wrap 32/64` of the exact result — ties the model to C++.
- ★ wrap32_eq_iff, wrap64_eq_iff: wrapping changes a value exactly when it leaves the range.
- ★ i32_exact_fits_i64: every exact + - * of two i32 values fits i64 (Clojure never throws there).
- ★ i32_pair_verdict: two `int` operands: jank agrees iff the true result fits i32, else a wrong value (N3/D1/R25).
- ★ i64_pair_verdict: any fixed pair with a `long`: jank agrees iff the true result fits i64, else "value where
  Clojure throws" (N1/LG2), for + - * and every mix of literal, let-bound and object operands.
- ★ fixed_eq_static: the fixed arithmetic (LG2a) is Clojure's static path for every fixed pair and operator.
- ★ fixed_vs_object_sub: the fixed jank differs from Clojure's Object `-` exactly when y = Long/MIN_VALUE and x - y
  fits (N5).
- ★ incdec_fixed_agree: inc/dec agree (throw and value) for every fixed integer not read as R5's BigInt.
- ★ abs_fixed_agree: abs agrees for every fixed integer, Long/MIN_VALUE included.
- ★ promoting_add_mul_agree: +' and *' agree with Clojure's static and Object paths for every fixed pair.
- ★ promoting_sub_wrong_iff: -' is wrong exactly when the true difference leaves i64 (D3/N4).
Axioms: results/r6-num-axioms.txt (propext, Classical.choice, Quot.sound only).
Not proved, searched instead: comparisons, min/max, == and compare across double/ratio/BigInt/BigDecimal (Float
is opaque to the kernel's decision procedures; the walk is complete over the value set, section 8). bv_decide on
a 64-bit multiplication overflow timed out (`small_mul_fits`); the Int/omega route replaced it.
