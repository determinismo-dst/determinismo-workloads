=====================================================================
jank main 94d32623 (upstream-r5/; compiler+runtime byte-identical to 7135b7708). Paths are under
upstream-r5/compiler+runtime/. Clojure is 1.12.3 (JDK 23), run through the job slots. jank was not built
or run; every jank value below is a hypothesis from boost (stock) or from the fix's own code run standalone.

Representation chosen: Java's own. `native_big_decimal` (include/cpp/jank/type.hpp 35-37, today boost's
cpp_dec_float<100>) becomes a class holding an unscaled `native_big_integer` (boost cpp_int, jank's BigInt
type) and an `i32` scale, with Java's BigDecimal arithmetic. Why not a scale field beside cpp_dec_float:
- the scale of a result is a function of exact digits (an exact quotient's least scale, a rounding's kept
  digits, a remainder's scale); a 128-digit approximation cannot carry them (1E+130M + 1 has scale 0 and
  131 digits), so S4/S7/X8 and the scale would keep fighting each other;
- printing (BigDecimal.toString), hashing (hasheq), = and compare all want the exact (unscaled, scale);
- with-precision (X6) rounds the exact result to p digits by a RoundingMode: impossible to do right after
  a cut at 121-128 digits;
- cpp_int is already jank's BigInt (same allocation behaviour: pointer_free object, limbs on the C++ heap).
The class supplies boost's interface where jank used it (str, convert_to<f64|integral|cpp_int>, is_zero,
compare, implicit construction from integers and doubles, explicit from text and from a BigInt) and
operators with every operand type math.hpp's templates meet (BigDecimal, every integral type, every
floating type, BigInt in jank::runtime, ratio_data in ratio.cpp), so math.hpp needs no change for R72.
The operators read the current MathContext (R72: none, exact; X6: *math-context*).

(2) Proofs (Jank/R8/Dec/Theorems.lean; axioms in results/r8-dec-axioms.txt)
---------------------------------------------------------------------------
For every input:
- roundQ_cases: round_quotient(n, d) is n/d or n/d + 1; roundQ_exact: exact division returns n/d in every
  mode; roundQ_unnecessary: UNNECESSARY throws exactly when n % d != 0.
- roundQ_half_choice and roundQ_half_ulp: in HALF_UP, HALF_DOWN, HALF_EVEN the result r satisfies
  2|r*d - n| <= d (within half a unit); roundQ_tie: on 2(n % d) = d HALF_UP goes up, HALF_DOWN down,
  HALF_EVEN to the even neighbour.
- roundQ_down, roundQ_up, roundQ_ceiling, roundQ_floor: DOWN truncates the magnitude (r*d <= n < (r+1)d),
  UP raises it (n <= r*d < n + d), CEILING/FLOOR move toward +inf / -inf by the sign.
- lt_pow_digits, pow_digits_le, digits_le_of_lt: 10^(digits n - 1) <= n < 10^(digits n).
- round_digits_le: decimal::round keeps at most p digits (the carry 10^p -> 10^(p-1) included).
- round_half_ulp: decimal::round in a HALF mode is within half a unit of the last kept place (its value at
  scale x.s - drop, times 10 after a carry, is r with 2|r*10^drop - |u|| <= 10^drop), sign kept.
- exact_scale_least: exact division's digits at scale preferred + k (k = max(twos, fives) > 0) end in no
  zero, so preferred + k is Java's max(preferred, least exact scale); with round 7's exact_sound and
  exact_complete (Jank.R7.Coord.Decimal) the value and the "Non-terminating" throw are right.
- add_scale (max), mul_scale (sum), neg_scale and abs_scale (kept), round_exact (precision 0 is exact).
Not proved (searched instead, (8)): context_divide (p digits, exact quotient stripped toward the preferred
scale), divideToIntegralValue in a context ("Division impossible"), toString/parse, doubleValue, valueOf.

(4) What is not exact
---------------------
- Exceptions compare by message text in the checks ("Divide by zero", "Non-terminating ...", "Division
  impossible", "Rounding necessary"); jank throws them as boxed strings (thrown? sees them), Clojure as
  ArithmeticException.
- Scales beyond the int range ("Overflow"/"Underflow", saturation of a zero's scale) are in the C++
  (check_scale) but neither searched nor in the Lean model.
- BigDecimal.valueOf(double) is built from std::to_chars' shortest digits (DecA8-1).
- *math-context* is a map in jank, a java.math.MathContext object in Clojure (DecA8-4).

  too); 2,000 random decimals agree on macOS.

  divide(mc) returns the p-digit rounding, or an exact quotient at the scale nearest the preferred one
