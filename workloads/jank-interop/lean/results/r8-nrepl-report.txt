2. PROOFS
======================================================================
(a) The codec (Jank/R8/Nrepl/Codec.lean), for EVERY table and EVERY state:
  ★ intern_spec / ★ internH_spec: the index a table returns holds the value (the stored value is the value, or
    equal to it under round 6's derived BEq), and every earlier index keeps its value. The table never trusts its
    hash: a candidate is returned only after the BEq check, so no lemma about Std.HashMap or about the hash is
    needed (the proof has no premise on BEq or Hashable).
  ★ internAt_spec: the same with the fast path, whenever the caller's `fast` flag implies the stored value IS the
    value (the driver's flag is a pointer comparison: ptrAddrUnsafe equality implies identity in Lean's runtime;
    that runtime fact is the only one used; a run with the fast path off reproduces the same graph, section 8).
  ★ encList_spec, ★ decList_holds, ★ decList_ext: the same for the thread list.
  join_split: splitting a state into components loses nothing (join ∘ split = id, by structure eta).
  ★ decode_encode: the tables only grow, and the code decodes to a state each of whose components (seven of the
    memory, one per thread, the same number of threads) is identical or round-6-equal to the original.
  ★ decodeC_ext: a code keeps its decoding when the tables grow.
  ★ same_code: two states given one code at any two times are both, component by component, identical or
    round-6-equal to one stored state.
  Not proved: that round 6's derived BEq is Lean's `=` (nREPLA6-2; Lean cannot derive LawfulBEq for these nested
  types and Float has no decidable equality). So the codec merges exactly the states round 6's exact graphs
  merged; injectivity with respect to `=` rests on nREPLA6-2 as before.
(b) The sdk's walk (Jank/R8/Nrepl/Walk.lean), on the sdk's own Decide.lean and Search.lean definitions:
  ★ nextPath_eq: `nextPath` (a `while` loop, unfolded with Lean.Loop.forIn_eq_of_monadTail) equals npLoop, the
    recursion "advance the last decision with an option left, drop those after it".
  ★ nextPathL_cons: on lists, nextPath (x :: xs) is x.value before nextPath xs when that exists, else x advanced
    alone when it has an option left, else none.
  ★ next_feeds, ★ prog_run: a program taking a finite tree's decisions with the sdk's `decide` (Decisions.next
    with its `% options` and first options after the given values) records exactly DT.run's decisions, for every
    tree whose decisions have ≥ 2 options and every decision limit at least the tree's height.
  ★ walk_paths: from the empty path, "run, then nextPath of what the run took" visits the tree's leaves in
    depth-first order, each once, and then stops (nextPath gives none).
  ★ walk_count, paths_length: so a complete walk runs exactly `leaves` timelines.
  ★ exhaust_complete: the sdk's `exhaust` over such a tree program (any maxRuns ≥ leaves) returns
    `.complete leaves`.
  leaves_node (rfl): a decision's timelines are the sum over its options: the recurrence both counters compute.
  Not proved (section 5): that interleavePB over tProg is such a tree whose subtree at a scheduler state depends
  only on that state (nREPLA6-1, and the counters' choice rule copied from ThreadSearch.lean 23-63); that
  round 6's countFrom (a partial def: opaque to proofs) or round 8's countLayers (array loops) evaluate the
  recurrence. These rest on reading and on exact reproductions: round 6's 21 walk results; this round's
  reproduction of round 6's T3 ≤0..≤6 and T9 ≤0..≤10 by a different counter; and new direct comparisons with
  the sdk's own walk on World T (results/r8-nrepl-walk.txt): `exhaust` over round 3's runT (the sdk's
  `interleave`, no preemption bound) on W1 (one client cloning) runs 264,832 timelines, the number the graph
  counter gives (Exact.lean interCount); `exhaust` over runTWith ≤b (interleavePB) on W2 (clone, describe)
  and W3 (two clients cloning) runs, for b = 0..3, exactly the layered counter's numbers.
