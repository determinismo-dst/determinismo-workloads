Q2 (Jank/R9/Nrepl/Theorems.lean), on round 2's model of core.jank response-for (Server.lean responseFor:
  (merge resp (select-keys req ["id" "session"])), Data.lean merge/conjMap/assocMap/selectKeys):
  ★ responseFor_nil_keys: for EVERY request, the message response-for makes from nil holds only keys taken from
    the request, each `same` as "id" or "session" (the message without content).
  ★ responseFor_keeps_keys: for EVERY request and EVERY reply map, the message keeps every key of the reply.
  ★ dropNils_no_nil: Q2's (filterv some? v) leaves no nil and only elements of v.
  ★ q2_messages: with Q2, for EVERY request and EVERY handler vector of maps and nils, every message is made from
    one of the vector's maps and keeps all its keys: no message is made from a nil.
  ★ stock_blank_out: on stock, an eval whose stdout is blank sends first a message holding only request keys.
  (JVal.same is a partial def: the statements carry it as List.find? returns it, never evaluate it.)
Q1 (Theorems.lean), on the Lean copy of fixes/Q1.diff's take-line (Fix.lean takeLine, termIdx):
  ★ takeLine_line_clean: a line take-line returns holds no \n and no \r, for every session input.
  ★ takeLine_none_iff: take-line asks for input (none) exactly when no terminator is buffered and no end of input
    is queued.
  ★ takeLine_split: when a terminator is buffered, line ++ terminator ++ the text left = the text, the terminator
    \n, \r or \r\n: nothing lost or invented.
  ★ takeLine_addInput: a line without terminators sent with \n to an empty input (no pending \r) is read back whole
    and the input is left empty (type-ahead).
nREPLA6-1, narrowed (Jank/R9/Nrepl/Tree.lean, TreeCheck.lean), on the sdk's own Decide/Search definitions and round
  8's Walk.lean:
  ★ agree_prefix: under Treelike, two paths with the same values below k give the same decisions below k and the
    same name and options at k.
  ★ build_run, ★ tree_of_treelike: EVERY run function `run : List Nat → List Taken` that is Treelike (bounded by D;
    each recorded value is the path's value modulo its options, 0 beyond the path; >= 2 options; causal: the k-th
    decision's existence, name and options depend only on the decisions before it) is exactly the run of the
    finite tree `build run D []`, which is well formed (WF), on EVERY path.
  ★ build_height: that tree's height is at most D.
  ★ exhaust_of_treelike: the sdk's `exhaust` over any `Source → Ended` whose path runs record `run`'s decisions
    and no violation completes with exactly that tree's leaves (via round 8's exh_gen, walk_paths, paths_length).
  ★ exhaust_worldT: the same instantiated at round 3's World T (runTWith with interleavePB at any budget, or the
    sdk's interleave): if World T's run function is Treelike and violation-free, exhaust over World T completes with
    the leaf count, depth first, each leaf once: round 8's walk_count/exhaust_complete apply to World T itself.
  Not proved: that World T's run function IS Treelike (it holds for code whose decisions all go through
    Decisions.next and that sees the source only through the values next returns: a property of round 3's
    Threads.lean, read, not proved), and that the subtree at a scheduler state is a function of that state (the
    graph counters' premise). Treelike is CHECKED on complete walks of World T (section 8).

- The fixed server's wait differs from nREPL's in what wakes it: nREPL's reader is woken by the stdin op on any
  connection (the session thread waits on the queue while the connection's handler thread reads); jank's wait
  reads the waiting connection's socket, so input sent through another connection is seen only when the waiting
  connection reads its next request (D3t). Needs a second thread per connection (R128), outside a local fix.
- QueuePollingReader's Java source is not in the project: the end of input is modeled as a queue entry used up by
  the read that meets it (nREPLA9-1), and skip-eol does not use it up (nREPLA9-4).
- nREPL's replies are read from its source, not run (its Java classes are missing; round 8's
  results/r8-nrepl-clj.txt).
