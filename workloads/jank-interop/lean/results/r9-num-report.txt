(4) What is not exact
---------------------
- Exceptions compare as "throws". The fixes throw boxed strings that thrown? sees ("integer overflow",
  "Value out of range for float: ...", "Value out of range for long: ..."), where Clojure throws
  ArithmeticException or IllegalArgumentException. Message texts use jank's double printing.
- V55's check runs wherever an operand is an object. Clojure's primitive paths differ:
  - (- -1 0 Long/MIN_VALUE) with literals is primitive in Clojure (nary inline: Long/MAX_VALUE). jank's
    3-arity is a fn call, so V55 throws.
  - (let [b (long x)] (- -1 b)) is primitive in Clojure. jank's long returns an object, so V55 throws.
  Both need an operand equal to Long/MIN_VALUE.
- V85 gives NaN-boxed values raw-word identity in hash keys. Clojure's identity depends on boxing:
  (let [x ##NaN] (contains? (hash-set x) x)) is false in Clojure (a primitive local boxed twice) and true
  with V85.
- The benchmark ran on the Mac (arm64, clang -O2, boost from deps/) in place of jank's x86-64 build. Treat
  the ratios as meaningful and the absolute ns as indicative. Allocation counts are C++ heap only (jank's
  GC box excluded).
