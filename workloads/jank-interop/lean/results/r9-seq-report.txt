T9-1. sort orders an input whose comparisons are not a total preorder differently (##NaN).
- Program: (sort [3 ##NaN 1 2]); (sort < [3 ##NaN 1 2]); (sort-by :v [{:v 3} {:v ##NaN} {:v 1} {:v 2}]).
- Clojure: (3 ##NaN 1 2) (TimSort: compare(NaN, 3) = 0, compare(1, NaN) = 0, compare(2, 1) = 1: one
  ascending run, kept). jank: (1 2 3 ##NaN) (std::stable_sort: halves [3 NaN] and [1 2], merged).
- Path: core.jank sort 5661-5670 / sort-by 5672-5682 -> core/seq.cpp sort 1098-1129 (less =
  runtime::compare(a, b) < 0) and 1131-1176 (comparator: true, false, else to_int(o) < 0) ->
  libstdc++ std::stable_sort. Clojure: core.clj sort -> java.util.Arrays.sort(a, comp) (TimSort),
  AFunction.compare. NaN compares 0 with every number in both (number.cpp real::compare 342-356,
  oref.hpp compare 830-860; Numbers.compare).
- Both are stable sorts and agree on every total preorder: proved for every list of fewer than 32
  elements and every integer key (SortProof.sorts_agree; for the replica's own sort, sort < ,
  sort compare and sort > on numbers without NaN: replica_sort_agree*), and searched (every pattern of <= 8
  elements, 400,000 random of 2..31). They differ on 35,698 of 87,380 lists over {0,1,2,NaN} of length
  <= 8 (first at length 4). Boolean comparators that are total but not strict (<=, >=, constantly
  true/false) agree too (complete to length 8 over 3 keys, 14 over 2; not covered by the proof).
- Tests: vt1-sort-with-a-nan, vt1b-sort-by-a-nan-key, vt1c-sort-with-a-boolean-comparator-and-a-nan;
  controls vt1d (leading NaN: [:nan 1 2 3] in both), vt1e (sort-by with <=: ties reversed alike).
- Status: new. Confidence: high (both sort algorithms validated on 15,888 cases: the replica of
  std::stable_sort against g++-15's own, the TimSort replica against Clojure 1.12.3).
- Cause: one design choice (std::stable_sort for Arrays.sort). Shares nothing with earlier ids.

(4) What is not exact
---------------------

- Sort: keys are integers or NaN; doubles, ratios and BigInts compare the same way (one numCompare).
  The agreement proof is generic (any element type with an integer key), stated on lists whose tags
  strictly increase.
  TimSort is replicated for n < 32 only; jank's std::stable_sort assumes the (n+1)/2 buffer is
  allocated (it is for any realistic n; otherwise libstdc++ falls back to __stable_sort_adaptive_resize
  or __inplace_stable_sort, not replicated).
- Chunk counts: the model counts realizations by chunk arithmetic over the map body, not by running
  objects; the Clojure side is validated (209 cases), the jank side is the code read.
- dedupe: the model counts outputs by `prior != x` (Clojure's (= prior input)): numbers of different
  kinds are not modeled.
- partition-all: n is a long or an integral double; a non-integral double, ratio or BigInt n is not
  modeled (Clojure casts each to a long; jank compares with =).
- SortedNaN: the trees are any binary search trees; neither balancing algorithm is replicated, so
  Clojure's root for a given insertion order is taken from the Clojure run.
- LazyState: one outer and one inner seq; Clojure's locals clearing is modeled as "a body that used
  its local once cannot increment again".
