The design in one paragraph
- A string is indexed by UTF-16 code units, as Java's. Its bytes stay UTF-8, which may also hold a
  surrogate (U+D800..U+DFFF) in its three-byte form, as WTF-8 does. A lone surrogate is a character of
  its own; a surrogate pair is always the four-byte form of its code point: string_builder joins a high
  surrogate followed by a low one when it appends them, so (str (subs s 0 1) (subs s 1)) and
  (apply str (seq s)) give s back byte for byte, and = stays byte equality.
- The bytes are read as pieces (jtl::utf16_piece_at, the rule round 8's R57a compare already uses): a
  complete 1-4 byte sequence as its lead announces, else one byte standing alone (unit 0xDC00 + byte).
  A piece of value >= U+10000 is two units; every other piece is one. Every function is total on every
  byte string.
- A character is one unit: nth/get/first of half a pair is that surrogate's three-byte form;
  `char` accepts 0..0xFFFF (surrogates included) and throws an object outside.
- Speed: persistent_string caches its unit count (a benign race, as immutable_string's hash). When the
  count equals the byte count (ASCII above all), count/nth/get/contains?/subs are stock's byte
  operations, O(1). Otherwise nth/get/subs walk from the start (O(n)), and index-of decodes both strings.

Jank/R9/Str/Units.lean. A Clojure string is a list of units us (each < 0x10000, lone surrogates
allowed); W9u's jank holds wtf8 us = (unitsToCps us).flatMap enc (round 2's pairing, each code point in
UTF-8, a surrogate in three bytes). For every such us (and ns):
* toUnits_wtf8 ★: the units W9u reads back (to_utf16) are us.
* count_wtf8 ★: count (utf16_length) is us.length.
* nth_wtf8 ★: nth at k < length gives the unit us[k] (locate + piece, persistent_string unit_at's
  general path; nthUnit_eq ★ for every byte string).
* hash_wtf8 ★: W9h's loop (u32) is String.hashCode of us (hashUnits_eq ★ for every byte string).
* indexOf_wtf8 ★, lastIndexOf_wtf8 ★: index-of / last-index-of (the general path: decode both, search)
  are Java's indexOf/lastIndexOf(String, int) on the units, for every start.
* subs_whole ★: (subs s 0 (count s)) is s byte for byte, for EVERY byte string.
* subs_tail_units ★: the units of (subs s k) are us from k on (both the fast byte path and
  utf16_substr, a cut pair included; tailGen_units ★ and drop_locate ★ for every byte string).
* subs_indexOf_startsWith ★: whenever index-of finds x from any start, the units of
  (subs s (index-of s x from)) begin with x's units.
* bitops_arith: for every byte, the C++ bit tests ((b & 0xE0) == 0xC0, ...) are the arithmetic ones the
  model uses (decide +kernel).
Not proved (searched instead, (8)): the three-argument subs on units as a byte-exact canonical result
(searched: every (i, j) on 4,955 texts, every byte string up to 4 bytes); the fast paths of index-of/
includes?/starts-with?/ends-with? (byte search when every piece is one byte); reverse and replace ""
(searched); the string_builder join (searched: join and apply-str round trips, 0 failures).

(5) Still left out, and why
========================================================================================================
- Regex on bytes, beyond W9r's step (section W9r below): a byte std::regex still sees bytes (`.` and
  negated classes match one byte of a non-ASCII character, \b's word characters are ASCII: R78-R85,
  V35, V36). W9r emulates a search from the middle of a pair, which Java starts after an empty match;
  it does not emulate a match Java starts inside a pair in the middle of an ordinary search (only a
  pattern matching a lone low surrogate but not the whole pair can do that, e.g. a class of low
  surrogates, which a byte regex cannot express anyway).
- What still differs with W9u: a pair built outside string_builder stays two three-byte halves (e.g.
  with-out-str printing the halves separately); count/nth/subs/hash/compare still see the right
  units, but = against the four-byte literal is false. A supplementary character literal (\😀, a read
  error in Clojure) is a four-byte character, and its int is the code point. W9-1 (char arrays).
  includes?/starts-with?/ends-with? and index-of match units (lone-surrogate needles too); replace with
  a string or char match, replace-first, trim and the case functions still work on bytes (exact for
  every canonical string unless the match is a lone surrogate meeting half a pair).
- clojure.string's other byte users: none found (escape walks count/nth, now units; last-index-of's
  default (count s) is units).
